# 📋 สเปกการออกแบบ: ระบบนำเข้าและลงทะเบียนเอกสารใหม่สู่ความรับผิดชอบ (Document Intake & Registration Engine)

**วันที่ออกแบบ:** ๒๐๒๖-๑๐-๑๖  
**สถานะ:** ผ่านการอนุมัติการออกแบบ (Approved Design Spec)  
**โครงการ:** WEPAPP (Royal Thai Army Armament & Inspection Web Application)  
**สถาปัตยกรรม:** Full-Stack Dynamic Registry (Approach 1)

## ๑. บทนำและปัญหาที่พบ (Background & Problem Statement)
ในปัจจุบัน ระบบ WEPAPP มีสารบัญเอกสารหลักจำนวน ๑๙ ฉบับที่ถูกกำหนดค่าตายตัวในโค้ด (Hardcoded Inventory) เมื่อผู้ใช้งานในหน่วยทหารมีเอกสารใหม่ (เช่น บัญชีคุมยุทโธปกรณ์เฉพาะกิจ, รายงานผลการตรวจสิ่งอุปกรณ์นอกแผน, หรือไฟล์บันทึกข้อความราชการใหม่) ระบบเดิมยังไม่มีช่องทางให้ผู้ใช้งานสามารถ **"นำเข้าและลงทะเบียนเอกสารใหม่เข้าสู่ระบบ"** ได้ด้วยตนเองผ่านหน้าเว็บ ทำให้ต้องให้ผู้พัฒนาแก้โค้ดเพื่อเพิ่มเอกสาร

## ๒. วัตถุประสงค์ (Objectives)
1. **การลงทะเบียนเอกสารผ่านหน้าเว็บ (Dynamic Web Intake):** มีหน้าต่าง Modal ให้ผู้ใช้ลากวางไฟล์ (Excel `.xlsx`, Word `.docx`, PDF `.pdf`) กรอกรหัส ชื่อ หมวดหมู่ และคำอธิบายเอกสาร แล้วลงทะเบียนเข้าสู่ระบบได้ทันที
2. **การแปลงและสร้างหน้าพรีวิวอัตโนมัติ (Autonomous Preview Generation):** สร้างไฟล์ HTML พรีวิวคมชัดระดับ 300 DPI และ PDF อัตโนมัติ เพื่อให้ผู้ใช้สามารถคลิกดูเนื้อหาออนไลน์ได้ทันทีเหมือนเอกสารทั้ง ๑๙ ฉบับเดิม
3. **การทำงานออฟไลน์ ๑๐๐% (Complete Air-Gapped / Offline Support):** ไม่พึ่งพา Cloud หรือบริการภายนอก จัดเก็บและประมวลผลภายในเครื่อง/เซิร์ฟเวอร์ของหน่วยเท่านั้น
4. **การเชื่อมต่อแดชบอร์ดแบบไร้รอยต่อ (Seamless Dashboard Integration):** แสดงการ์ดเอกสารในสารบัญเอกสารหลัก (Tab 4) อัปเดตตัวนับจำนวนฉบับ และสามารถเลือกนำเข้าสู่คิวงานประจำสัปดาห์ (Tab 1) ได้ทันที

## ๔. ข้อกำหนดทางเทคนิคส่วนหลังบ้าน (Backend API Specification)

### ๔.๑ รายการ API Endpoints (FastAPI)
1. `GET /api/documents/custom`
   * **ผลลัพธ์:** ส่งกลับรายการเอกสารที่ผู้ใช้งานลงทะเบียนทั้งหมด (`custom_documents.json`)
2. `POST /api/documents/register`
   * **การรับข้อมูล:** `multipart/form-data`
     * `file`: UploadFile (ไฟล์ `.xlsx`, `.docx`, หรือ `.pdf`)
     * `code`: str (รหัสเอกสาร)
     * `title`: str (ชื่อเอกสาร)
     * `category`: str (หมวดหมู่: `inspection`, `inventory`, `memo`, `general`)
     * `desc`: str (คำอธิบาย)
     * `is_in_weekly_queue`: bool (นำเข้าคิวงานประจำสัปดาห์หรือไม่)
     * `queue_desc`: Optional[str] (คำอธิบายคิวงาน)
   * **การประมวลผล:**
     * บันทึกไฟล์ต้นฉบับลงโฟลเดอร์ uploads
     * เรียกใช้งาน `document_intake_engine.py` เพื่อแปลงไฟล์เป็น HTML พรีวิว และ PDF
     * บันทึกข้อมูลลง `custom_documents.json`
   * **ผลลัพธ์:** `200 OK` พร้อมข้อมูลเอกสารที่สร้างเสร็จ
3. `DELETE /api/documents/custom/{doc_id}`
   * **การประมวลผล:** ลบข้อมูลจาก `custom_documents.json` และลบไฟล์ที่เกี่ยวข้องใน uploads อย่างปลอดภัย
   * **ผลลัพธ์:** `200 OK`
4. `PATCH /api/documents/custom/{doc_id}/toggle-queue`
   * **การประมวลผล:** สลับสถานะ `is_in_weekly_queue` (True/False)

## ๕. โมดูลการแปลงไฟล์อัตโนมัติ (`backend/document_intake_engine.py`)

### ๕.๑ การประมวลผลไฟล์ Excel (`.xlsx`)
* ใช้ไลบรารี `openpyxl` อ่านโครงสร้างชีต
* สร้างเอกสาร HTML Preview:
  * บรรจุหัวเอกสารตามชื่อไฟล์/ชื่อเอกสาร
  * สกัดตารางข้อมูลทุกเซลล์ จัดชิดซ้าย/กึ่งกลาง/ชิดขวาตามชนิดข้อมูล
  * รวมเซลล์ตาม `ws.merged_cells.ranges`
  * บังคับใช้ฟอนต์ **TH Sarabun PSK** และมาตรฐานเส้นตารางสีดำ 1px
* เรนเดอร์สร้างไฟล์ `.pdf` ผ่านคำสั่ง Headless Microsoft Edge/Chrome

### ๕.๒ การประมวลผลไฟล์ Word (`.docx`)
* ใช้ไลบรารี `python-docx` สกัดย่อหน้า (Paragraphs) และตาราง (Tables)
* เรนเดอร์เป็นโครงสร้าง HTML หน้ากระดาษ A4 แนวตั้ง ฟอนต์ TH Sarabun PSK
* เรนเดอร์สร้างไฟล์ `.pdf` ควบคู่กัน

### ๕.๓ การประมวลผลไฟล์ PDF (`.pdf`)
* จัดเก็บไฟล์ และสร้างหน้า HTML พรีวิวแบบ Embed PDF Viewer สำหรับเปิดอ่านได้โดยตรงบนเบราว์เซอร์

## ๖. ข้อกำหนดทางเทคนิคส่วนหน้าบ้าน (Frontend UI/UX Specification)

### ๖.๑ ปุ่มเปิดหน้าต่างนำเข้า (`btn-open-doc-intake`)
* ติดตั้งปุ่ม `[+ นำเข้าเอกสารใหม่สู่ระบบ]` บน Header แถบนำทาง และบนส่วนหัวของแท็บ ๔ (สารบัญเอกสารทั้งหมด)

### ๖.๒ หน้าต่าง Modal นำเข้าเอกสาร (`#modal-doc-intake`)
* กล่อง Drag & Drop รับไฟล์ `.xlsx`, `.docx`, `.pdf` พร้อมพรีวิวชื่อและขนาดไฟล์
* ฟอร์มกรอกข้อมูล: รหัสเอกสาร, ชื่อเอกสาร, หมวดหมู่, คำอธิบาย
* เช็กบ็อกซ์ `นำเข้าสู่คิวงานประจำสัปดาห์ (Weekly Checklist)`
* แอนิเมชัน Loading ขณะกำลังอัปโหลดและประมวลผลสร้างพรีวิว
* การแจ้งเตือน Toast Message เมื่อดำเนินการสำเร็จ

### ๖.๓ การแสดงผลบนแดชบอร์ด (`dashboard.js`)
* รวมรายการเอกสารหลัก (๑๙ ฉบับเดิม) เข้ากับเอกสารที่ผู้ใช้นำเข้าใหม่ (Dynamic Custom Docs)
* เพิ่มการ์ดเอกสารใหม่ใน Tab 4 พร้อมปุ่ม:
  * `[HTML พรีวิว]` (เปิดดูออนไลน์)
  * `[ดาวน์โหลดต้นฉบับ]` (ดาวน์โหลดไฟล์ที่อัปโหลดมา)
  * `[PDF]` (ดูเอกสารฉบับพิมพ์)
  * `[ลบเอกสาร]` (มีกล่องยืนยันก่อนลบ)
* อัปเดตตัวเลข Badge แสดงจำนวนเอกสารรวม (เช่น `๑๙ + ๑ ฉบับ`)
* อัปเดตตารางคิวงานประจำสัปดาห์ใน Tab 1 ทันทีหากเลือกนำเข้าคิวงาน

## ๗. แผนการทดสอบและความปลอดภัย (Testing & Resilience Plan)
1. **การทดสอบความถูกต้องของข้อมูล (Data Integrity Test):**
   * ทดสอบอัปโหลดไฟล์ Excel ที่มีสูตรและการรวมเซลล์ ตรวจสอบว่าหน้าพรีวิวแสดงผลตรงเป๊ะ
   * ทดสอบอัปโหลดไฟล์ Word และ PDF
2. **การทดสอบความทนทานต่อข้อผิดพลาด (Resilience & File-Lock Safety):**
   * ทดสอบกรณีไฟล์ถูกเปิดค้างไว้ในเครื่อง (File Lock / Permission Denied) ระบบต้องแจ้งเตือนอย่างปลอดภัย ไม่แครช
3. **การทดสอบ End-to-End API (ASGI Test):**
   * ทดสอบเรียก Endpoints `GET`, `POST`, `PATCH`, `DELETE` ผ่าน pytest/httpx
   * ยืนยันสถานะ HTTP 200 OK ทุกจุด
