# Automation Orchestrator Plan

## 🎯 Vision (10× Outcome)
Create a **self‑contained Python state‑machine orchestrator** that can drive the full 10‑phase Full‑Stack Application development pipeline **without human‑intervention**, while still preserving a **Human‑in‑the‑Loop checkpoint** at each phase for approval.  The goal is to reduce the end‑to‑end development time from weeks to **≈1 day** for a standard Next.js‑based project.

## 🚧 Bottleneck Disruption
| Current Bottleneck | Why it Slows Us | How the Orchestrator Removes It |
|--------------------|----------------|---------------------------------|
| Manual hand‑off between phases (scaffolding → blueprint → UI → tests) | Requires context copying, repeated command‑line work | State machine automatically passes the **output JSON** of each phase as the **input context** for the next phase |
| Re‑reading requirements & architecture files | Human spends time parsing PDF/Markdown | Built‑in **PDF → Text** (PyMuPDF) and **Jinja2** templating to generate architecture artefacts on‑the‑fly |
| Missing verification before committing code | Bugs surface late in CI | Each phase includes an **LLM‑driven verification step** that runs before the next phase proceeds |

## 🛠️ Implementation Details
- **State Persistence** – Each phase stores its output JSON under `orchestrator/state/phase_<n>.json`. The next phase reads this file automatically.
- **LLM Integration** – Calls `ask_llm(phase, name, context)` (wrapper around OpenAI/Claude) to generate artefacts. The wrapper logs prompts and responses for audit.
- **Human‑In‑The‑Loop** – After each phase, the orchestrator calls `pause_for_human(i, state_dir)`. This prints a prompt and waits for a **YES** input from the user before continuing.
- **Error Handling** – If any LLM call returns an error or verification fails, the orchestrator logs the failure, aborts, and notifies the user.
- **Virtual Environment** – All Python dependencies live in `.venv` created at project root (`python -m venv .venv`). Activate before running the orchestrator.

## 📦 Minimum Viable Pivot (MVP) – First 3 Phases
1. **Scaffold** the Next.js app.
2. **Ingest** the repository blueprint JSON and the PDF you supplied (`เริ่มต้นตั้งค่าและเลือกโหมดทำงาน.pdf`). Convert PDF to plain text with PyMuPDF and store as `pdf_text.txt`.
3. **Create Zone‑folders** and a **README** for each zone.

If the MVP runs without errors, the remaining 7 phases can be rolled out incrementally.
