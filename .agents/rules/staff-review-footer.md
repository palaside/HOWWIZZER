# 📝 STAFF REVIEW FOOTER ENGINE RULES (บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน)
**Rule ID:** `RULE-STAFF-REVIEW-FOOTER-V1`  
**Scope:** บังคับใช้กับบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน (Staff Review Footer / Staff Initials Block) ในเอกสารราชการ, บันทึกข้อความ, สำเนาคู่ฉบับ (Dual-Copy File Copy), Word (.docx), Excel (.xlsx), และ HTML/Print Templates ทั้งหมด

---

## 📌 1. CORE MANDATE & UNIVERSAL PRINCIPLE
บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน เป็นส่วนประกอบสำคัญตามระเบียบงานสารบรรณทหารในเอกสาร **"สำเนาคู่ฉบับ"** เพื่อบันทึกประวัติเจ้าหน้าที่ผู้จัดทำและตรวจสอบเอกสาร มีข้อกำหนดทางเรขาคณิต (Mathematical Geometry) ที่ต้องแม่นยำ ๑๐๐% เพื่อความเป็นระเบียบและมาตรฐานสูงสุด

---

## 📐 2. MANDATORY DUAL-AXIS ALIGNMENT (มาตรฐาน ๒ แกนดิ่งคู่ขนาน)

```
        แกนที่ ๑ (ยศ)    แกนหน้าที่          วันที่    แกนที่ ๒ (เดือน ปี)
        │               │                 │       │
        จ.ส.อ.           ร่าง/ตรวจ                 มิ.ย. ๖๙
        ส.ท. วรากรฯ      พิมพ์/ทาน          ๑๘     มิ.ย. ๖๙
        │                                         │
        ▼                                         ▼
  (แนว 'จ' กับ 'ส'                          (แนว 'ม' แถวบนและล่าง
   ตรงกันเป๊ะ 100%)                          ตรงกันเป๊ะ 100%)
```

### กฎข้อที่ 1: แกนดิ่งตัวอักษรตัวแรกของยศ (Rank First-Character Axis)
* **นิยามแกน:** ตัวอักษรตัวแรกของยศแถวบน (เช่น `จ` ของ `จ.ส.อ.`) และตัวอักษรตัวแรกของยศ/ชื่อแถวล่าง (เช่น `ส` ของ `ส.ท. วรากรฯ`) ต้องเริ่มต้นที่ **แนวเส้นดิ่งเดียวกันเป๊ะ ๑๐๐%**
* **ข้อกำหนด CSS/Layout:**
  - ต้องตั้งค่าเป็น `text-align: left`
  - **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามใช้ `text-align: center` ในคอลัมน์ยศเด็ดขาด เพราะจะทำให้ยศที่สั้นกว่าถูกดึงเข้าไปตรงกลางและหลุดแนวตัวอักษรแรก

### กฎข้อที่ 2: แกนดิ่งเดือนและปี (Month Axis Alignment)
* **นิยามแกน:** ตัวอักษรตัวแรกของเดือนแถวบน (เช่น `ม` ของ `มิ.ย. ๖๙`) และตัวอักษรตัวแรกของเดือนแถวล่าง (เช่น `ม` ของ `มิ.ย. ๖๙`) ต้องเริ่มต้นที่ **แนวเส้นดิ่งเดียวกันเป๊ะ ๑๐๐%**
* **โครงสร้างช่องวันที่ (Day Column):**
  - แถวล่างมีตัวเลขวันที่ (เช่น `๑๘` หรือ `๑๙`) จัดวางในคอลัมน์วันที่ชิดขวา อยู่ด้านหน้าแกนเดือน
  - แถวบนเว้นว่างช่องวันที่ไว้ ส่งผลให้เดือนของทั้งสองแถวเริ่มที่พิกัด x เดียวกันโดยสมบูรณ์

## 🏛️ 3. STANDARD 4-COLUMN GRID ARCHITECTURE (โครงสร้าง ๔ คอลัมน์มาตรฐาน)

กำหนดขนาดคอลัมน์มาตรฐานสำหรับ HTML/CSS Grid ดังนี้:

| คอลัมน์ที่ | หน้าที่ / ข้อมูล | ความกว้างมาตรฐาน | การจัดวาง (Alignment) | ตัวอย่างข้อมูล |
|:---:|:---|:---:|:---:|:---|
| **๑** | ยศและชื่อเจ้าหน้าที่ | `26mm` | `text-align: left;` | `จ.ส.อ.` / `ส.ท. วรากรฯ` |
| **๒** | บทบาทหน้าที่ | `22mm` | `text-align: left;` | `ร่าง/ตรวจ` / `พิมพ์/ทาน` |
| **๓** | วันที่ (เฉพาะผู้พิมพ์/ทาน) | `8mm` | `text-align: right; padding-right: 2.5mm;` | ` ` (แถวบน) / `๑๘` (แถวล่าง) |
| **๔** | เดือน และ พ.ศ. | `20mm` | `text-align: left;` | `มิ.ย. ๖๙` / `มิ.ย. ๖๙` |

* **มาตรฐานขนาดและน้ำหนักฟอนต์:**
  - ขนาดตัวอักษร: `13.5pt`
  - น้ำหนักฟอนต์: **Thin (`font-weight: 300`)** ตาม `RULE-PROD-DOC-ENGINE-V1 Rule 9`
  - ความสูงบรรทัด: `line-height: 1.25;`

## 📍 4. VERTICAL SPACING & POSITIONING (ระยะห่างและตำแหน่งมาตรฐาน)

1. **ระยะห่าง ๕ Enter จากผู้ลงนาม (5-Enter Invariant):**
   - บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน ต้องเคาะลงมาเป็นระยะ **๕ Enter (๒๒ มม. / Pt(55))** ใต้บรรทัดตำแหน่งของผู้บังคับบัญชาผู้ลงนาม (เช่น `ผบ.ป.๔ พัน.๔ ร้อย.๒`)
2. **การจัดชิดขวาของหน้ากระดาษ (Right Alignment):**
   - คอนเทนเนอร์หลักต้องจัดชิดขวาของหน้ากระดาษ:
     ```css
     .memo-footer-staff {
         margin-top: 22mm;
         display: flex;
         justify-content: flex-end;
     }
     ```

## 🛡️ 5. TAG-DEPTH SAFETY & COMPILER INTEGRATION (ระบบความปลอดภัยของแท็ก)

1. **Tag-Depth Safety Guard:**
   - สคริปต์คอมไพล์เอกสาร (`doc_generation_service.py`) ต้องใช้ตัววิเคราะห์ระดับชั้นของแท็ก (`depth += 1` เมื่อพบ `<div`, `depth -= 1` เมื่อพบ `</div>`) เพื่อค้นหาจุดสิ้นสุดที่แท้จริงของบล็อก
   - **ข้อห้ามเด็ดขาด:** ห้ามใช้ Regular Expression แบบกวาดปิด `</div>\s*</div>` เด็ดขาด เพราะจะกลืนแท็กปิด `</div>` ของหน้ากระดาษหน้า ๑ ทำให้หน้า ๒ เรนเดอร์ซ้อนเข้าไปในหน้า ๑
2. **Dual-Copy Engine Binding:**
   - **ฉบับตัวจริง (`_ฉบับจริง.html`):** ระบบต้องซ่อนบล็อกนี้อัตโนมัติ (`<div class="memo-footer-staff" style="display: none !important;"></div>`)
   - **สำเนาคู่ฉบับ (`_สำเนาคู่ฉบับ.html`):** ระบบต้องแสดงบล็อกนี้พร้อมวันที่เสนอเซ็นที่คำนวณถูกต้องตามวันทำการ (จันทร์-พฤหัสบดี)

## 📏 6. RIGHT-EDGE YEAR ALIGNMENT (กฎบังคับ: ปี พ.ศ. ขนานกับขอบขวาเนื้อหา)

* **ตัวเลขปี พ.ศ. ตัวสุดท้าย** ของบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน (เช่น `๖๙` ของ `มิ.ย. ๖๙`) ต้องอยู่ **แนวเส้นดิ่งเดียวกับขอบขวาของพื้นที่เนื้อหา (Content Right Edge)** เป๊ะ ๑๐๐% ขนานกับขอบขวาของข้อความเนื้อหา
* **ห้ามชิดขอบกระดาษ** และห้ามล้ำเข้าไปในระยะ Margin ขวาของหน้า (ห้ามใช้ค่าติดลบ หรือ absolute ที่เกินกรอบเนื้อหา)
* ต้องตรวจด้วย Visual QA (Print-Grade ≥ 2.5x) ทุกครั้งที่คอมไพล์ ห้ามเคลมว่าเสร็จจนกว่าจะผ่าน
* กฎนี้ใช้กับทั้ง HTML, Word (.docx) และ Excel (.xlsx) และต้องคงอยู่ทุกครั้งที่รีเฟรช/คอมไพล์ใหม่ (Zero Regression)

## 🖨️ 7. DUAL-COPY ENGINE (กฎบังคับ: ระบบพิมพ์แพ็กเกจคู่ขนาน ๒ ชุด)

* **๑ คำสั่งพิมพ์ ต้องส่งออกคู่ขนาน ๒ ชุดเสมอ:**
  1. **ฉบับตัวจริง** (`_ฉบับจริง`) — ไม่มีข้อความ "สำเนาคู่ฉบับ" และซ่อนบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน
  2. **สำเนาคู่ฉบับ** (`_สำเนาคู่ฉบับ`) — มีข้อความ "สำเนาคู่ฉบับ" และแสดงบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน พร้อมปี พ.ศ. ตามกฎข้อ ๖
* ทั้ง ๒ ชุดต้องมาจาก Source เดียวกัน (SSOT) เนื้อหา เลย์เอาต์ และการแบ่งหน้าต้องเหมือนกัน ต่างกันเฉพาะส่วนของสำเนาคู่ฉบับเท่านั้น
* ห้ามส่งออกเพียงชุดเดียว และห้ามให้ชุดใดชุดหนึ่งหลุดหายเมื่อรันคอมไพล์ซ้ำ
