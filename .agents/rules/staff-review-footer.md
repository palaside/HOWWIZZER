# 📝 STAFF REVIEW FOOTER ENGINE RULES (บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน)
**Rule ID:** `RULE-STAFF-REVIEW-FOOTER-V1`  
**Scope:** บังคับใช้กับบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน (Staff Review Footer / Staff Initials Block) ในเอกสารราชการ, บันทึกข้อความ, สำเนาคู่ฉบับ (Dual-Copy File Copy), Word (.docx), Excel (.xlsx), และ HTML/Print Templates ทั้งหมดในโปรเจกต์

---

## 📌 1. CORE MANDATE & UNIVERSAL PRINCIPLE
บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน เป็นส่วนประกอบสำคัญตามระเบียบงานสารบรรณทหารในเอกสาร **"สำเนาคู่ฉบับ"** เพื่อบันทึกประวัติเจ้าหน้าที่ผู้จัดทำและตรวจสอบเอกสาร มีข้อกำหนดทางเรขาคณิต (Mathematical Geometry) ที่ต้องแม่นยำ ๑๐๐% เพื่อความเป็นระเบียบและมาตรฐานสูงสุด

---

## 📐 2. MANDATORY DUAL-AXIS & RIGHT BOUNDARY ALIGNMENT (มาตรฐาน ๒ แกนดิ่งคู่ขนาน + แนวระนาบขอบขวาเนื้อหา)

```
        แกนที่ ๑ (ยศ)    แกนหน้าที่          วันที่    แกนที่ ๒ (เดือน)        ขอบขวาเนื้อหา (ปี พ.ศ.)
        │               │                 │       │                                │
        จ.ส.อ.           ร่าง/ตรวจ                 มิ.ย.                            ๖๙
        ส.ท. วรากรฯ      พิมพ์/ทาน          ๑๘     มิ.ย.                            ๖๙
        │                                         │                                │
        ▼                                         ▼                                ▼
  (แนว 'จ' กับ 'ส'                          (แนว 'ม' แถวบนและล่าง           (ตัวอักษรสุดท้ายของปี
   ตรงกันเป๊ะ 100%)                          ตรงกันเป๊ะ 100%)                ขนานขอบขวาเนื้อหาเป๊ะ 100%)
```

### กฎข้อที่ 1: แกนดิ่งตัวอักษรตัวแรกของยศ (Rank First-Character Axis)
* **นิยามแกน:** ตัวอักษรตัวแรกของยศแถวบน (เช่น `จ` ของ `จ.ส.อ.`) และตัวอักษรตัวแรกของยศ/ชื่อแถวล่าง (เช่น `ส` ของ `ส.ท. วรากรฯ`) ต้องเริ่มต้นที่ **แนวเส้นดิ่งเดียวกันเป๊ะ ๑๐๐%**
* **ข้อกำหนด CSS/Layout:**
  - ต้องตั้งค่าเป็น `text-align: left`
  - **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามใช้ `text-align: center` ในคอลัมน์ยศเด็ดขาด เพราะจะทำให้ยศที่สั้นกว่าถูกดึงเข้าไปตรงกลางและหลุดแนวตัวอักษรแรก

### กฎข้อที่ 2: แกนดิ่งเดือนและปี (Month Axis Alignment)
* **นิยามแกน:** ตัวอักษรตัวแรกของเดือนแถวบน (เช่น `ม` ของ `มิ.ย. ๖๙`) และตัวอักษรตัวแรกของเดือนแถวล่าง (เช่น `ม` ของ `มิ.ย. ๖๙`) ต้องเริ่มต้นที่ **แนวเส้นดิ่งเดียวกันเป๊ะ ๑๐๐%**
* **โครงสร้างช่องวันที่ (Day Column):**
  - แถวล่างมีตัวเลขวันที่ (เช่น `๑๘` หรือ `๑๙`) จัดวางในคอลัมน์วันที่ชิดขวา อยู่ด้านหน้าแกนเดือน
  - แถวบนเว้นว่างช่องวันที่ไว้ ส่งผลให้เดือนของทั้งสองแถวเริ่มที่พิกัด x เดียวกันโดยสมบูรณ์

### กฎข้อที่ 3: แนวระนาบปี พ.ศ. ขนานกับขอบขวาของเนื้อหา (Content Right Margin Boundary Alignment)
* **นิยามแนวระนาบ:** ตัวอักษรตัวสุดท้ายของปี พ.ศ. (เช่น เลข `๙` ของ `๖๙` หรือ `๒๕๖๙`) ต้องอยู่ใน **แนวเส้นดิ่งเดียวกันกับขอบขวาของเนื้อหา (Right Content Margin)**
* **ระยะปลอดภัยขอบกระดาษ:** บล็อกต้องขนานกับขอบขวาของเนื้อหาแต่ **ต้องไม่ชิดขอบกระดาษ** โดยต้องรักษาระยะ Margin/Padding ด้านขวาของกระดาษ ๒๐ มม. (20mm) ตามระเบียบสารบรรณไว้อย่างสมบูรณ์แบบ ห้ามทะลุหรือล้นออกนอกแนวขอบเนื้อหาเด็ดขาด

## 🏛️ 3. STANDARD 4-COLUMN GRID ARCHITECTURE (โครงสร้าง ๔ คอลัมน์มาตรฐาน)

กำหนดขนาดคอลัมน์มาตรฐานสำหรับ HTML/CSS Grid ดังนี้:

| คอลัมน์ที่ | หน้าที่ / ข้อมูล | ความกว้างมาตรฐาน | การจัดวาง (Alignment) | ตัวอย่างข้อมูล |
|:---:|:---|:---:|:---:|:---|
| **๑** | ยศและชื่อเจ้าหน้าที่ | `26mm` | `text-align: left;` | `จ.ส.อ.` / `ส.ท. วรากรฯ` |
| **๒** | บทบาทหน้าที่ | `22mm` | `text-align: left;` | `ร่าง/ตรวจ` / `พิมพ์/ทาน` |
| **๓** | วันที่ (เฉพาะผู้พิมพ์/ทาน) | `8mm` | `text-align: right; padding-right: 1.5mm;` | ` ` (แถวบน) / `๑๘` (แถวล่าง) |
| **๔** | เดือน และ พ.ศ. | `max-content` | `text-align: left;` | `มิ.ย. ๖๙` / `มิ.ย. ๖๙` |

* **มาตรฐานขนาดและน้ำหนักฟอนต์:**
  - ขนาดตัวอักษร: `13.5pt`
  - น้ำหนักฟอนต์: **Thin (`font-weight: 300`)** ตาม `RULE-PROD-DOC-ENGINE-V1 Rule 9`
  - ความสูงบรรทัด: `line-height: 1.25;`

## 📍 4. VERTICAL SPACING & POSITIONING (ระยะห่างและตำแหน่งมาตรฐาน)

1. **ระยะห่าง ๕ Enter จากผู้ลงนาม (5-Enter Invariant):**
   - บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน ต้องเคาะลงมาเป็นระยะ **๕ Enter (๒๒ มม. / Pt(55))** ใต้บรรทัดตำแหน่งของผู้บังคับบัญชาผู้ลงนาม (เช่น `ผบ.ป.๔ พัน.๔ ร้อย.๒`)
2. **การจัดขนานขอบขวาของเนื้อหา (Right Content Flush Alignment):**
   - คอนเทนเนอร์หลักต้องจัดวางด้วย Flexbox กว้างเต็มความกว้างเนื้อหา (`width: 100%`) และดันชิดขวา (`justify-content: flex-end`):
     ```css
     .memo-footer-staff {
         margin-top: 22mm;
         width: 100%;
         display: flex;
         justify-content: flex-end;
     }
     .staff-grid {
         display: grid;
         grid-template-columns: 26mm 22mm 8mm max-content;
         font-size: 13.5pt;
         line-height: 1.25;
         font-weight: 300;
     }
     .staff-col-rank { text-align: left; }
     .staff-col-role { text-align: left; }
     .staff-col-day { text-align: right; padding-right: 1.5mm; }
     .staff-col-month { text-align: left; }
     ```

## 🛡️ 5. TAG-DEPTH SAFETY & DUAL-COPY ENGINE INTEGRATION (ระบบความปลอดภัยของแท็กและพิมพ์คู่ขนาน)

1. **Tag-Depth Safety Guard:**
   - สคริปต์คอมไพล์เอกสาร (`doc_generation_service.py`, `informal_equipment_service.py`) ต้องใช้ตัววิเคราะห์ระดับชั้นของแท็ก (`depth += 1` เมื่อพบ `<div`, `depth -= 1` เมื่อพบ `</div>`) เพื่อค้นหาจุดสิ้นสุดที่แท้จริงของบล็อก
   - **ข้อห้ามเด็ดขาด:** ห้ามใช้ Regular Expression แบบกวาดปิด `</div>\s*</div>` เด็ดขาด เพราะจะกลืนแท็กปิด `</div>` ของหน้ากระดาษหน้า ๑ ทำให้หน้า ๒ เรนเดอร์ซ้อนเข้าไปในหน้า ๑
2. **Dual-Copy Engine Binding:**
   - **ฉบับตัวจริง (`_ฉบับจริง.html` / Original Copy):** ระบบต้องซ่อนบล็อกนี้อัตโนมัติ (`<div class="memo-footer-staff" style="display: none !important;"></div>` หรือไม่เรนเดอร์ใน DOM ของฉบับจริง)
   - **สำเนาคู่ฉบับ (`_สำเนาคู่ฉบับ.html` / Dual Copy):** ระบบต้องแสดงบล็อกนี้พร้อมวันที่เสนอเซ็นที่คำนวณถูกต้องตามวันทำการ (จันทร์-พฤหัสบดี) โดยตัวอักษรตัวสุดท้ายของปี พ.ศ. ขนานกับขอบขวาของเนื้อหาพอดีเป๊ะ ๑๐๐%
