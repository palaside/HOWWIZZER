# 🏛️ PRODUCTION-GRADE DOCUMENT & FORENSIC ENGINE RULES
**Rule ID:** `RULE-PROD-DOC-ENGINE-V1`  
**Scope:** บังคับใช้กับงานสร้าง, โคลน, วิศวกรรมย้อนรอย (Reverse Engineering), และเรนเดอร์เอกสารราชการ, แบบฟอร์ม ทบ., เอกสารพยานหลักฐานศาล, Excel (.xlsx), Word (.docx), และ HTML/Print Templates ทั้งหมด

---

## 📌 1. CORE MANDATE & PHILOSOPHY
เมื่อต้องพัฒนาหรือสร้างเอกสารราชการ/ตารางข้อมูล ห้ามทำงานแบบ "ปะผุเฉพาะหน้า (Visual-Only Hacks)" เด็ดขาด การเรนเดอร์ที่ถูกต้องทางสายตาต้องอยู่บนรากฐานของ **Data Integrity, Mathematical Precision, และ OpenType Typography Standards 100%**

## 📐 2. MANDATORY ENGINEERING RULES

### กฎข้อที่ 1: การรักษาประเภทข้อมูลและการคำนวณใน Excel (Data-Type-Preserving Number Formatting)
* **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามแปลงข้อมูลตัวเลขเป็นสตริงข้อความ (เช่น บันทึกเป็น `"๓๓๒,๗๑๒.๐๐"`) ใน Data Model ของ Excel โดยเด็ดขาด เพราะจะทำให้ฟังก์ชัน `=SUM()`, `=AVERAGE()` และการคำนวณทางบัญชีกลายเป็นข้อผิดพลาด (Formula Error)
* **ข้อบังคับ (MANDATORY IMPLEMENTATION):**
  - บันทึกค่าลงเซลล์ Excel เป็นตัวเลขดิบ (Raw Decimal/Float/Integer) เสมอ
  - กำหนดการแสดงผลเป็นเลขไทยผ่าน **Culture Number Format Token** ของ Microsoft Excel:
    ```python
    # จำนวนเงินทศนิยม 2 ตำแหน่ง
    cell.value = 332712.00
    cell.number_format = '[$-th-TH,26]#,##0.00'

    # จำนวนนับ / จำนวนเต็ม
    cell.value = 6
    cell.number_format = '[$-th-TH,26]#,##0'
    ```

### กฎข้อที่ 2: การควบคุมการแสดงผลและสลับ Glyph ที่ระดับ Font Engine (OpenType Feature Layout)
* **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามแปลงรหัสตัวอักษรแบบ Hardcoded ในเนื้อหาข้อมูล (Content Layer) จาก ASCII 0–9 เป็น Thai Unicode ๐–๙ ในกรณีที่เอกสารต้องการรองรับการค้นหา (Ctrl+F), ยิง Barcode หรือคัดลอก (Copy-Paste)
* **ข้อบังคับ (MANDATORY IMPLEMENTATION):**
  - ในเนื้อหาดิจิทัล คงค่ารหัสตัวอักษรตั้งต้นเป็น ASCII `0-9` (U+0030 ถึง U+0039)
  - สั่งการให้ Font Engine (เช่น TH Sarabun PSK) สลับ Glyph การวาดเส้นเป็นเลขไทยเฉพาะระดับการแสดงผลบนหน้าจอและกระดาษพิมพ์ผ่าน CSS OpenType Feature Tags:
    ```css
    .thai-numeral-display {
        font-variant-numeric: tabular-nums;
        font-feature-settings: "locl" 1, "numr" 1; /* บังคับสลับ Glyph เลขไทยที่ Font Engine */
    }
    ```

### กฎข้อที่ 3: สัญญาข้อมูลและตัวแบ่งประเภทเชิงความหมาย (Schema Contract & Context-Aware Rules)
* **ข้อบังคับ (MANDATORY IMPLEMENTATION):**
  - ทุกตารางต้องมีไฟล์พิมพ์เขียว (`table_layout.json`) เป็น **Single Source of Truth (SSOT)** ระบุ `data_type` ชัดเจนในทุกคอลัมน์ (`currency`, `integer`, `code_string`, `text`)
  - **Context-Aware Protection:** รหัสครุภัณฑ์สากล (เช่น NATO Stock Number `1015-00-722-9752`, รหัสรุ่น `M.19`, ขนาดยาง `900-20`) ต้องได้รับการปกป้องตามมาตรฐานเทคนิค ห้ามทำ Blind Replacement เหมารวม

---

### กฎข้อที่ 4: การแยกชั้นเนื้อหากับโครงสร้างด้วยเกราะป้องกัน AST (AST-Safe Parsing Isolation)
* **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามรันฟังก์ชัน Replace ตัวอักษรบนก้อนโค้ด HTML/XML ทั้งก้อน เพราะจะทำให้ตัวเลขใน Tag Attributes พัง เช่น `<td width="100">` กลายเป็น `width="๑๐๐"`
* **ข้อบังคับ (MANDATORY IMPLEMENTATION):**
  - กระบวนการประมวลผลข้อความต้องกระทำเฉพาะบน `TextNode` ของ DOM / AST เท่านั้น
  - ห้ามแตะต้อง Element Attributes (`width`, `height`, `colspan`, `rowspan`, `style`, `class`, `id`) โดยเด็ดขาด

---

### กฎข้อที่ 5: สถาปัตยกรรมตารางเดี่ยวผืนเดียว (Unified Single Master Grid Architecture)
* **ข้อบังคับ (MANDATORY IMPLEMENTATION):**
  - แบบฟอร์มที่มีส่วนหัว (Header Box) และตารางข้อมูล (Data Grid) ห้ามแยกเป็น 2 ตารางอิสระจากกัน
  - ต้องผูกเข้ากับ **Unified Single Master Grid** (เช่น 15 Columns) ผืนเดียวกันทั้งหน้ากระดาษ:
    - **ใน HTML:** ส่วนหัวทั้งหมดต้องอยู่ร่วมใน `<thead>` เดียวกันกับหัวคอลัมน์ข้อมูล คุมด้วย `<colgroup>` สัดส่วนเปอร์เซ็นต์รวม 100.0000%
    - **ใน Word (.docx):** ต้องเป็น `<w:tbl>` เดียวทั้งหน้ากระดาษ กำหนด `<w:tblGrid>` ขนาดรวมคงที่ (เช่น 13,650 dxa) เพื่อรับประกันว่าเส้นแนวตั้งทุกช่องจะตรงกันเป็นเส้นเดียว 100% ปราศจากการเยื้อง

### กฎข้อที่ 6: กฎการคำนวณวันเสนอเซ็นหนังสือราชการ (Submission Window & Holiday Avoidance Rule)
* **บริบท:** เอกสารประจำสัปดาห์ (เช่น สด.๑, บันทึกตรวจประจำสัปดาห์) จะต้องส่งให้ผู้บังคับบัญชาตรวจและลงนามก่อนถึงวันตรวจสิ้นสัปดาห์ (วันศุกร์)
* **ข้อกำหนด (MANDATORY INVARIANTS):**
  1. วันที่บนหัวบันทึกข้อความ และวันที่ในช่องผู้ร่าง/พิมพ์/ทาน **ต้องเป็นวันทำการระหว่างวันจันทร์ ถึง วันพฤหัสบดี เท่านั้น**
  2. **ห้ามตรงกับวันหยุดราชการหรือวันหยุดชดเชยเด็ดขาด:** หากวันจันทร์เป็นวันหยุด ให้ขยับวันเริ่มต้นเป็น **วันอังคาร**
  3. **กำหนดส่งช้าที่สุด (Latest Threshold):** ต้อง **ไม่เกินวันพฤหัสบดี** (หรือวันทำการสุดท้ายก่อนวันหยุดยาว)
  4. **ข้อห้ามเด็ดขาด (STRICT PROHIBITION):** ห้ามลงวันที่เสนอหนังสือหรือวันที่ร่าง/พิมพ์/ทาน เป็นวันศุกร์เด็ดขาด เพื่อป้องกันความย้อนแย้งทางธุรการ

---

### กฎข้อที่ 7: ระบบพิมพ์แพ็กเกจคู่ขนาน ๒ ชุด (Dual-Copy Print Engine: Original & File Copy)
* **บริบท:** เมื่อสั่งพิมพ์ชุดเอกสารราชการเพื่อเสนอเซ็น ต้องพิมพ์ออกมาเป็นคู่ขนาน ๒ ชุดเสมอ
* **ข้อกำหนด (MANDATORY INVARIANTS):**
  1. **ชุดที่ ๑: ฉบับตัวจริง (Original):**
     * หัวกระดาษปกติ (ไม่มีคำว่าสำเนาคู่ฉบับ)
     * สำหรับเสนอผู้บังคับบัญชาลงนามตัวจริง เพื่อนำส่งหน่วยเหนือ (ผบ.ป.๔ พัน.๔)
     * **ซ่อนบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน โดยสมบูรณ์** (`display: none !important;` หรือตัดออกจาก DOM ในฉบับจริง)
  2. **ชุดที่ ๒: สำเนาคู่ฉบับ (File Copy):**
     * มีข้อความ `(สำเนาคู่ฉบับ)` ปรากฏที่มุมบนขวา
     * มีตารางกำกับ **ผู้ร่าง/ตรวจ** และ **พิมพ์/ทาน** ที่มุมล่างขวา เคาะลงมา ๕ Enter (๒๒ มม.) ใต้ผู้ลงนาม โดยตัวอักษรตัวสุดท้ายของปี พ.ศ. ขนานกับขอบขวาของเนื้อหาเป๊ะ ๑๐๐% พร้อมระบุวันที่เสนอเซ็นจริง (จันทร์–พฤหัสบดี) สำหรับเจ้าหน้าที่ลงนามย่อ (Paraf) และเก็บเข้าแฟ้มสารบรรณของหน่วย
  3. **การสั่งพิมพ์:** ๑ คำสั่งพิมพ์บนแดชบอร์ด จะต้องส่งออกเอกสารทั้ง ๒ ชุดนี้ควบคู่กันเสมอ

### กฎข้อที่ 8: มาตรฐานความคมชัดสูงระดับงานพิมพ์ (Print-Grade 300 DPI Rendering Standard)
* **บริบท:** ป้องกันปัญหาภาพพรีวิวแตก เส้นตารางเบลอ หรือตัวหนังสือจางบนหน้าจอความละเอียดสูง
* **ข้อกำหนด (MANDATORY INVARIANTS):**
  1. ทุกการจับภาพหน้าจอ (Screenshot), ภาพ Vision พรีวิว, และการแปลงหน้าเอกสาร ต้องใช้ `device_scale_factor >= 2.5` (ความละเอียดเทียบเท่า ๒๔๐–๓๐๐ DPI Print Grade) เสมอ
  2. ห้ามใช้ค่าเริ่มต้น Screen 96 DPI (`device_scale_factor: 1.0`) เด็ดขาด
  3. เปิดใช้งาน `-webkit-font-smoothing: antialiased;` และคงสภาพเส้นตารางสีดำสนิท คมกริบ ไร้รอยหยักเบลอ ๑๐๐%

---

### กฎข้อที่ 9: มาตรฐานน้ำหนักตัวอักษรแบบแยกชั้นหัวข้อ-เนื้อหา (Heading Bold vs. Non-Heading Thin Typography Standard)
* **บริบท:** ป้องกันความทึบตันของหน้ากระดาษ และสร้างการตัดกันทางสายตา (Visual Contrast Hierarchy) ที่ชัดเจน สง่างามตามแบบแผนราชการ
* **ข้อกำหนด (MANDATORY INVARIANTS):**
  1. **ส่วนที่ไม่ใช่หัวข้อ (Non-Heading Elements) ต้องใช้ฟอนต์แบบ Thin / Light เสมอ:**
     - ตัวเนื้อความในบันทึกข้อความ (`.memo-body`, `<p>`, `<td>` เนื้อหา)
     - ผลการตรวจในเซลล์ตาราง (เช่น `มี สป.ครบ`, `ตรงตามบัญชีคุม`, `ถูกต้อง`, `ไม่มี`)
     - รายละเอียดและจำนวนของสิ่งที่ส่งมาด้วย
     - ข้อย่อยการตรวจ (เช่น `๑.๑`, `๑.๒`, `๓.๑`)
     - บล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน (`.staff-grid`)
     - **ค่า CSS:** บังคับใช้ `font-weight: 300;` (หรือ `font-weight: 100;` ใน Sarabun OpenType Engine)
  2. **ส่วนหัวข้อ (Heading Elements) ให้คงความหนา Bold เสมอ:**
     - หัวเรื่องหลัก (เช่น `บันทึกข้อความ`, `แบบรายงานผลการตรวจอาวุธ...`)
     - ป้ายกำกับนำ (เช่น `ส่วนราชการ`, `ที่`, `วันที่`, `เรื่อง`, `เรียน`, `อ้างถึง`, `สิ่งที่ส่งมาด้วย`)
     - หัวตาราง (เช่น `ลำดับ`, `หัวข้อการตรวจ`, `ผลการตรวจ`)
     - หัวข้อหมวดใหญ่ (เช่น `๑. การควบคุมทางบัญชี`, `๒. การปรนนิบัติบำรุง`)
     - **ค่า CSS:** ใช้ `font-weight: bold;` หรือ `font-weight: 700;`
  3. **การจัดวางบล็อกผู้ร่าง/ตรวจ/พิมพ์/ทาน (Staff Review Footer Placement & Right Content Alignment):**
     - ต้องอยู่ใต้บรรทัดตำแหน่งผู้ลงนาม (เช่น `ผบ.ป.๔ พัน.๔ ร้อย.๒`) **๕ Enter (22 mm / Pt 55)**
     - **การขนานกับขอบขวาของเนื้อหา:** จัดวางชิดขวาของเนื้อหา (`display: flex; justify-content: flex-end; width: 100%;`) โดยให้ตัวอักษรตัวสุดท้ายของปี พ.ศ. (เช่น เลข `๙`) ตรงกับแนวเส้นดิ่งขอบขวาของเนื้อหาพอดีเป๊ะ แต่ **ไม่ชิดขอบกระดาษ** (คงระยะ Margin ขวา ๒๐ มม. ไว้เสมอ)
     - ตัวประมวลผลแทนที่บล็อกต้องใช้ระบบคำนวณความลึกแท็ก (`Tag Depth Tracking`) ห้ามตัดกลืนแท็กปิด `</div>` ของหน้ากระดาษหลักเด็ดขาด
